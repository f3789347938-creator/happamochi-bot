# 葉っぱもち カジノ

通常ポーカー・上級ポーカー・ブラックジャックを、LINEと一般のブラウザで遊ぶ追加機能。
ゲームのエンジン・画像・画面はこのプロジェクト用に実装している。

## 入口と操作

- LINEに「カジノ」「ポーカー」「上級ポーカー」「ブラックジャック」と送ると案内カードを返信する。
- 「ヘルプ」の「カジノ」、または「ゲーム一覧・遊び方」からも開ける。案内やリンクを開くだけではポイントを消費しない。
- `/casino?mode=draw|duel|blackjack` が設定に応じて専用LIFF、または `/static/casino/` を開く。
- 練習コインは端末だけに保存する。葉っぱもちのポイントとは交換・合算しない。
- 本番のポイントは既存 `user_profiles.points` を使う。プレイ中のゲームはページを閉じても保存され、次回再開できる。

## ルール

| ゲーム | 参加額 | 進め方 |
| --- | --- | --- |
| 通常ポーカー | 100 / 500 / 1,000 | 5枚から交換するカードを選び、1度だけ交換。0枚・5枚交換も可能 |
| 上級ポーカー | 200 / 500 / 800 / 1,000 ＋参加額の10% | ディーラーと5カードドロー。交換前後にベット、各ラウンドのレイズは最大1回 |
| ブラックジャック | 100 / 500 / 1,000 / 2,500 | ヒット・スタンド・最初の2枚でダブル。ソフト17を含めディーラーは17以上で止まる |

通常ポーカーの払戻倍率（元の参加額を含む）：ロイヤル100、ストレートフラッシュ50、
フォーカード25、フルハウス7、フラッシュ5、ストレート4、スリーカード2、
ツーペア1.5、J以上のワンペア1、10以下のワンペア0.5、役なし0。
ブラックジャックは通常勝利2倍、最初の2枚のブラックジャック2.5倍、引き分け1倍。
スプリットと保険はない。上級ポーカーの最大支出は参加額の5.1倍（手数料を含む）。
画面の「払戻し」と「収支」は別の値で、収支は払戻しからそのゲームの総支出を引いたもの。

ディーラーのポーカー判断は自分の手札・公開されたベット状況・乱数だけを使う。
プレイヤーの手札や山札を見て判断しない。山札はサーバーの暗号学的乱数でシャッフルする。

## ローカルで動かす

```sh
npm ci
npm run casino:test
npm run build
npm run casino:demo
```

`artifacts/casino/happamochi-casino-demo.html` はCSSとゲームエンジンを内蔵した練習版。
ダウンロードしてブラウザで開ける。実際のポイントを使うにはサーバー版が必要。
通常の静的確認は `python3 -m http.server 8187 --directory public` を実行し、
`http://localhost:8187/static/casino/` を開く。ポイントAPIは静的サーバーでは動作しない。
Python PlaywrightとChromiumがある環境では、別のターミナルから
`python tests/casino/browser-smoke.py --base-url http://localhost:8187/static/casino/ --output-dir artifacts/casino/qa`
で3ゲームと4画面サイズの練習UIを確認できる。これはLINE実アカウントでの検証ではない。

## APIと保存

`public/static/casino/engine.mjs` が3ゲーム共通の純粋なルール実装。
本番ではサーバーだけが完全なゲーム状態を持ち、`publicRound` によって山札と伏せ札を除いて返す。
ブラウザ上のエンジンは練習専用であり、クライアントが決めた結果をポイントAPIには送らない。

| API | 用途 |
| --- | --- |
| `GET /api/casino/config` | 公開LIFF ID、有効状態、ルール |
| `GET /api/casino/session` | 残高、累計収支、再開するゲーム、直近20件の履歴 |
| `GET /api/casino/history` | 同じデータ形式の履歴取得 |
| `POST /api/casino/start` | `{mode, stake, requestId}` |
| `POST /api/casino/action` | `{roundId, version, action, discards?, requestId}` |

config以外は `Authorization: Bearer <LIFF access token>` が必要。
LINEのトークン検証・チャネル照合・プロフィール取得でユーザーを確定し、クライアント指定のユーザーIDは受け付けない。
全APIレスポンスは `Cache-Control: no-store`。トークンや完全なゲーム状態を履歴レスポンスに含めない。

`casino_receipts` への1回のINSERTとSQLiteトリガーで、残高・ゲーム・`point_ledger` を同時に確定する。
同一リクエストの再送は二重課金・二重払戻しにならず、異なる内容で同じIDを使うと409になる。
ブラウザの未確定操作もLINEアカウント別に保存する。アカウントを切り替えた際に、前のアカウントの操作を新しい残高で再送しない。
ユーザーごとに進行中のゲームは1件。バージョンが古い操作を受け付けない。
ダブルや配った時点での勝利でも、払戻し前に必要な参加額を持っていることを検証する。
未終了ゲームを時間切れで消したり、自動で負けにしたりしない。

## 本番への追加

**このブランチを現状のまま本番全体へ上書きデプロイしない。**
作成時点のGitHub mainは `553e596` で、本番には `official-20260929` の公式サイトなど、
このmainにない更新がある。先に実際に本番へデプロイした最新ソースへ、この追加分を取り込む。
この機能のために既存のログイン・お知らせFlexの高さやデザインは変更していない。

1. 最新の本番ソースへ追加分を取り込み、既存ルート・ゲーム・公式サイトを維持してビルドする。
2. 本番D1を `wrangler d1 export` でリポジトリ外の安全な場所へバックアップする。
3. 最新側のマイグレーション番号と重複しないことを確認して `0030_casino.sql` を適用する。必要なら取り込み時に番号を調整する。既存テーブルの削除・初期化は禁止。
4. 既存Botと同じProviderのLINEログインチャネルに専用LIFFを登録する。エンドポイントは `https://line-group-bbs.pages.dev/static/casino/`、サイズFull、スコープprofile。
5. Pagesの環境変数 `CASINO_LIFF_ID` にそのIDを設定する。別チャネルの場合は `CASINO_LOGIN_CHANNEL_ID` も設定する（既定値は既存の `2011492233`）。
6. `CASINO_ENABLED` をまだ設定しない状態でプレビューし、3種類の練習と既存機能を確認する。
7. 最新ソースからデプロイ後に `CASINO_ENABLED=true` を設定し、LINE実機で本人の残高、1ゲームの開始・再開・払戻し・履歴を確認する。

本番の残高に接続する設定がない場合は練習で遊べる。既存パズルやサバイバルのLIFF IDを流用しない。
緊急時は `CASINO_ENABLED` を無効にしてポイント操作を止められる。DBや履歴は削除せず、再有効化後に途中のゲームを再開する。
